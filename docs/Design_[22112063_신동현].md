## 1. Introduction

본 문서는 'KTX-AutoReserve' 코레일 KTX 승차권 자동 예매 시스템의 소프트웨어 설계(Design)를 설명합니다.

클래스 다이어그램을 통해 시스템의 정적 구조와 주요 구성 요소(클래스) 간의 관계 및 책임을 정의합니다. 시퀀스 다이어그램은 KTX 예약 요청, 파라미터 검증, 열차 탐색 및 예약 시도, 예외 처리, SMS 알림 발송 등 주요 기능에 대한 객체 간의 동적 상호작용 흐름을 상세히 보여줍니다. 스테이트 머신 다이어그램은 예약 자동화 프로세스가 실행되는 동안 발생할 수 있는 상태 변화를 모델링합니다. 또한, 시스템 구현을 위한 운영 환경 요구사항과 본 문서에서 사용된 용어에 대한 정의를 포함합니다.

핵심 설계 원칙은 관심사의 분리(Separation of Concerns)를 기반으로 하며, Controller → Service → 전문 Service 계층으로 책임을 명확히 분리하는 데 중점을 둡니다. 이를 통해 각 클래스가 단일 책임을 갖도록 설계하여 유지보수성과 확장성을 확보합니다.

## 3. Sequence diagram

### 3.1 Reserve KTX Ticket

아래는 사용자가 API를 호출하여 KTX 예약이 완료되는 전체 흐름의 Sequence Diagram이다.

![seq_reserve_ktx_ticket](https://donghyeun-blog-images.s3.us-east-1.amazonaws.com/reserveTicketSequence.jpg)

**KTX 티켓 예약 (Reserve KTX Ticket)**

사용자가 Swagger UI 또는 HTTP 클라이언트에서 `GET /ticket/reserve` 요청을 전송하면, TicketController는 파라미터의 존재 여부, 타입, 시간 순서를 검증합니다. 검증을 통과하면 TicketController는 TicketService의 `reserve()` 메서드를 호출하여 자동화 프로세스를 시작합니다. TicketService는 WebDriverFactory를 통해 Chrome 브라우저를 실행하고 WebDriver 인스턴스를 생성합니다. 이후 KorailLoginService를 호출하여 코레일 웹사이트에 로그인하고, SearchCriteriaService를 통해 출발역·도착역·날짜·시간 조건을 입력하고 조회를 실행합니다. TicketReservationService는 열차 목록을 순회하며 조건에 맞는 KTX를 탐색하고 예약 버튼을 클릭합니다. 예약이 성공하면 TicketService는 성공 메시지를 반환하고 WebDriver 세션을 종료합니다. 최종적으로 TicketController는 사용자에게 200 OK 응답을 반환합니다.

---

### 3.2 Handle Exception

아래는 잘못된 파라미터 요청이 들어왔을 때 예외가 처리되는 흐름의 Sequence Diagram이다.

![seq_handle_exception](https://donghyeun-blog-images.s3.us-east-1.amazonaws.com/handlerSequence.png)

**예외 처리 (Handle Exception)**

사용자가 필수 파라미터가 누락되거나 타입이 잘못된 요청을 전송하면, TicketController는 파라미터 바인딩 단계에서 예외를 감지합니다. Spring은 `MissingServletRequestParameterException` 또는 `MethodArgumentTypeMismatchException`을 발생시키고, GlobalExceptionHandler가 이를 감지하여 예외 유형에 맞는 사용자 친화적 오류 메시지를 생성합니다. 최종적으로 400 Bad Request 상태 코드와 함께 오류 메시지를 사용자에게 반환합니다.

---

### 3.3 Search & Attempt Reservation

아래는 브라우저 자동화를 통해 열차를 탐색하고 예약을 시도하는 흐름의 Sequence Diagram이다.

![seq_search_attempt_reservation](https://donghyeun-blog-images.s3.us-east-1.amazonaws.com/SearchAttemptSequence.png)

**열차 탐색 및 예약 시도 (Search & Attempt Reservation)**

TicketService가 SearchCriteriaService를 통해 조회 조건을 입력하면, TicketReservationService는 코레일 웹의 열차 목록을 순회하며 Time Window(출발 시각 범위)와 KTX Filter(KTX 여부) 조건을 검사합니다. 조건에 맞는 열차가 없을 경우 Polling 대기 후 재조회를 반복합니다. 최대 재시도 횟수를 초과하면 실패 메시지를 반환합니다. 조건에 맞는 열차가 발견되면 예약 버튼을 클릭하고, 예약 성공 여부를 확인합니다. 예약 버튼이 비활성화(좌석 없음)된 경우에는 재탐색으로 돌아갑니다. 예약이 성공하면 true를 반환하고 다음 단계로 진행합니다.

---

### 3.4 Send SMS Notification

아래는 예약 성공 후 SMS 알림을 발송하는 흐름의 Sequence Diagram이다.

![seq_send_sms_notification](https://donghyeun-blog-images.s3.us-east-1.amazonaws.com/sendSMSSequence.png)

**SMS 알림 발송 (Send SMS Notification)**

예약이 성공적으로 완료되고 사용자가 전화번호 파라미터를 입력한 경우, TicketService는 SmsSender의 `send()` 메서드를 호출합니다. SmsSender는 AWS SNS 클라이언트를 통해 예약 완료 메시지를 구성하고 지정된 전화번호로 SMS를 발송합니다. AWS SNS가 처리 결과를 반환하면, SmsSender는 결과를 TicketService에 반환합니다. AWS SNS 호출이 실패하더라도 오류를 로깅하고 API 응답은 정상적으로 반환됩니다.

## 4. State machine diagram

아래는 KTX-AutoReserve 예약 자동화 프로세스의 State Machine Diagram을 나타낸 것이다.

![ktx_autoreserve_state_machine](https://donghyeun-blog-images.s3.us-east-1.amazonaws.com/stateMachineDiagram.png)

예약 자동화 프로세스는 **Idle** 상태에서 API 요청이 수신되면 시작됩니다. **Validating** 상태에서 파라미터를 검증하고, 검증 실패 시 **Failed** 상태로 전이하여 400 응답을 반환합니다. 검증이 통과하면 **Initializing** 상태로 이동하여 브라우저를 실행합니다. 브라우저 초기화 후 **Authenticating** 상태에서 코레일 로그인을 수행하며, 로그인 실패 시 **Failed** 상태로 전이합니다. 로그인 성공 후 **Searching** 상태에서 조건에 맞는 열차를 반복 탐색합니다. 탐색 중 조건에 맞는 열차를 발견하면 **Reserving** 상태로 전이하여 예약 버튼을 클릭합니다. 예약 실패(좌석 없음) 시 **Searching** 상태로 복귀하고, 최대 재시도 초과 시 **Failed** 상태로 전이합니다. 예약 성공 시 **Completed** 상태로 전이하며, 전화번호 파라미터가 존재하면 SMS 발송 후 최종 완료됩니다.

## 5. Implementation requirements

- **OS**: macOS 또는 Windows 10 이상 (Python 실행 환경 지원)

- **Python**: 3.12 이상 (selenium-driverless 호환)

- **패키지/실행**: pip, uvicorn (`pip install -r requirements.txt`)

- **Browser**: Google Chrome (selenium-driverless가 드라이버 자동 처리)

- **Network**: 코레일 웹사이트 접근을 위한 인터넷 연결 필요

- **AWS 계정**: SMS 알림 기능 사용 시 AWS SNS 계정 및 설정 필요

- **환경 변수**: 코레일 로그인 아이디/비밀번호, AWS 자격증명을 환경 변수 또는 설정 파일로 관리

## 6. Glossary

● **KTX-AutoReserve**: 코레일 KTX 승차권 자동 예매 시스템 이름

● **selenium-driverless**: CDP(DevTools)로 Chrome을 직접 제어하는 자동화 라이브러리. Runtime 도메인 누수 없이 동작하고 클릭이 isTrusted=true로 인식되어 코레일 매크로 감지(-8002/-8004)를 우회한다.

● **CDP (Chrome DevTools Protocol)**: 브라우저를 제어·관찰하는 프로토콜. selenium-driverless는 이를 통해 입력을 native(isTrusted) 이벤트로 전달하여 웹 요소 탐색·클릭·입력을 수행한다.

● **Explicit Wait**: 특정 조건이 만족될 때까지 최대 대기 시간을 설정하고 기다리는 동기화 방식. 동적 렌더링 환경에서 요소가 나타날 때까지 안정적으로 대기한다.

● **Polling**: 일정 시간 간격으로 상태를 반복 확인하는 전략. 좌석 가용성이 변동하는 환경에서 지속적으로 예약 기회를 탐색한다.

● **Time Window**: 사용자가 지정한 열차 출발 시각 허용 범위(timeStart ~ timeEnd).

● **KTX Filter**: 열차 목록에서 KTX 열차만을 선별하는 조건.

● **Sequence Diagram**: 객체 간의 동적 상호작용을 시간 순서로 모델링하여 나타낸 다이어그램.

● **State Machine Diagram**: 객체 또는 시스템이 생명주기 동안 가질 수 있는 모든 상태와 전이 조건을 정의한 다이어그램.

● **AWS SNS (Simple Notification Service)**: Amazon Web Services의 메시지 발송 서비스. SMS 문자 발송에 활용된다.

● **Orchestration**: 여러 서비스의 실행 순서와 흐름을 조율하는 제어 방식. TicketService가 전체 예약 자동화 흐름을 오케스트레이션한다.

● **Headless Mode**: 화면 출력 없이 브라우저를 백그라운드에서 실행하는 방식.
